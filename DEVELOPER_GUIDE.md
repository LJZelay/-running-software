Here are a list of aspects we need to go through before a PR gets approved for merging

Required:
1. Ensure that there are no merge conflicts
2. Every piece of code should ideally be classed out correctly based on what the one committing was assigned to do
3. maintain clean architecture practices
4. It has to work based on the standard (either simulation or tests) that was assigned or worked on.
5. Naming should be consistent and makes sense

Nice to have:
1. Code looks clean and readable (it working is more important, but would be great for future work)
2. Documentation is robust
